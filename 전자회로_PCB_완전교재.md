  A1.  OPAMP / Comparator
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ 개념부터: OPAMP가 뭔가 ──────────────────────────────────────────────────┐

  OPAMP(Operational Amplifier, 연산 증폭기)는 두 입력 단자의 전압 차이를
  엄청난 배율(개방 루프 이득 Aol = 100,000배 이상)로 증폭하는 소자다.

  핵심은 "두 입력의 차이"만 증폭한다는 점이다.

    Vout = Aol × (V+ - V-)

  근데 Aol = 100,000이면 V+ - V- 가 1mV만 달라도
  Vout = 100V → 실제로는 전원 전압(VCC)에 막혀 포화(Saturation)된다.

  그래서 현실에서는 항상 "피드백(Feedback)"을 걸어서 이득을 낮춰 쓴다.
  피드백이 걸리면 OPAMP는 V+ = V- 가 되도록 스스로 출력을 조절한다.
  이것이 "가상 단락(Virtual Short)" 법칙이다.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ 내부 구조: 어떻게 동작하나 ─────────────────────────────────────────────┐

  OPAMP 내부는 크게 3단으로 나뉜다:

  1단: 차동 입력단 (Differential Pair)
       - MOSFET M1, M2가 쌍으로 구성
       - V+와 V- 입력을 받아 "차이 신호"만 통과시킴
       - 공통 노이즈(전원 잡음, 온도 등)는 같이 들어오므로 서로 상쇄
         → 이것이 CMRR (Common Mode Rejection Ratio): 공통 모드 제거비

  2단: 이득단 (Gain Stage)
       - 1단에서 나온 미약한 차동 전류를 전압으로 변환 후 증폭
       - 보상 커패시터 Cc 삽입 → 위상 여유(Phase Margin) 확보
         → Cc 없으면 이 단계에서 위상이 180° 뒤집히고
           피드백이 정궤환(Positive Feedback)이 되어 발진(Oscillation)함

  3단: 출력단 (Output Stage)
       - 소스 팔로워 또는 푸시풀(Push-Pull) 구조
       - 낮은 출력 저항 → 부하를 충분히 구동

  ┌ 위상 여유(Phase Margin)가 뭔가 ─────────────────────────────────────────┐

  OPAMP에 피드백을 걸면 루프 안에서 신호가 한 바퀴 돌 때
  이득이 1(0dB)이 되는 주파수에서 위상이 얼마나 지연됐느냐를 보는 것.

  위상이 -180° 지연되면 → 피드백이 "같은 방향"으로 더해짐 → 발진!
  그래서 이득=1 될 때 위상이 -180°보다 얼마나 여유 있는지가 위상 여유.

  위상 여유 ≥ 45°  → 안정 동작
  위상 여유 = 0°   → 발진 직전 (실제 설계에서 절대 용납 안 됨)
  위상 여유 = 60°  → 가장 이상적 (과도 응답도 깔끔)

  보상 커패시터 Cc를 키우면 → 극점(Pole)이 낮은 주파수로 내려옴
  → 이득=1이 되는 주파수(Unity Gain Bandwidth)도 낮아짐
  → 위상 여유 증가하지만 속도(대역폭)가 희생됨

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ 실제 장비 연계: EO-IR 카메라에서 OPAMP는 어디에 붙나 ─────────────────┐

  FLIR G5-550HD 같은 EO-IR 카메라의 신호 경로:

  │                                                                         │

  TIA(Transimpedance Amplifier)의 동작:
  - OPAMP의 (-) 입력에 포토다이오드 연결
  - 피드백 저항 Rf를 통해 전류가 전압으로 변환
  - Vout = -Iph × Rf  (가상단락: V- ≈ V+ = 0V 유지)
  - Rf가 클수록 감도↑, 하지만 노이즈도 √Rf에 비례해서 증가
  - Cf(피드백 커패시터)로 대역폭과 안정성 조절

  노이즈 공식:
  Vn = √(4kT × Rf × BW)    [V_rms]
  k = 볼츠만 상수, T = 절대온도, BW = 대역폭

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Comparator: OPAMP와 어떻게 다른가 ──────────────────────────────────────┐

  Comparator는 피드백이 없는 OPAMP다.
  즉, 개방 루프 상태로 쓰는 것 — 출력이 항상 포화(HIGH 또는 LOW)됨.

  V+ > V-  →  Vout = VCC  (HIGH)
  V+ < V-  →  Vout = GND  (LOW)

  "어느 쪽이 큰지"만 판정하는 1비트 ADC라고 생각하면 된다.

  실제 장비 연계: Pan-Tilt 구동부의 리밋 스위치
  ─────────────────────────────────────────────────────────────────────────
  Pan-Tilt(수평/수직 회전 마운트)는 카메라를 원하는 방향으로 돌린다.
  모터가 너무 돌아가면 기계가 부서지므로 "한계 위치" 감지가 필요하다.

  ┌──────────────────────────────────────────────────────────────────────┐
  │                                                                      │
  │  광학 엔코더 출력 (Hall 센서 or 포텐셔미터)                          │
  │         │                                                            │
  │         │ 전압 Vsensor (각도에 비례)                                │
  │         ▼                                                            │
  │  Comparator (+) ←── Vsensor                                         │
  │  Comparator (-) ←── Vlimit (기준 전압, 예: 2.7V = 270°)            │
  │         │                                                            │
  │         │ Vsensor > Vlimit → Vout = HIGH → MCU에 인터럽트          │
  │         │ → "이 이상 돌지마!" 신호 → 모터 드라이버 차단             │
  │         ▼                                                            │
  │     MCU / FPGA (PID 제어기)                                         │
  │                                                                      │
  └──────────────────────────────────────────────────────────────────────┘

  히스테리시스(Schmitt Trigger) — 떨림 방지:
  Vsensor가 기준값 근처에서 미세하게 흔들리면 Comparator 출력이
  HIGH/LOW를 수백 번 빠르게 오가는 채터링(Chattering) 발생.
  → 양의 피드백(소량)으로 "ON 기준"과 "OFF 기준"에 차이를 둬서 해결.
  → 예: ON = 2.8V, OFF = 2.6V (0.2V 히스테리시스 밴드)

  A2.  MOSFET 기반 증폭기
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ MOSFET이 뭔가 — 물리부터 ───────────────────────────────────────────────┐

  MOSFET은 게이트(Gate) 전압으로 소스(Source)→드레인(Drain) 전류를 제어하는
  소자다. 스위치이면서 동시에 증폭기가 될 수 있다.

  작동 원리:
  - Gate에 전압을 가하면 → 절연체(SiO2) 아래에 전기장 형성
  - 전기장이 채널(Channel)에 전도성 있는 전자층을 유도
  - 이 채널을 통해 Drain → Source 방향으로 전류 흐름
  - Vgs (Gate-Source 전압)가 클수록 채널이 두꺼워져 전류 증가

  MOSFET 3가지 동작 영역:

  1) 차단(Cut-off): Vgs < Vth → 전류 안 흐름 (스위치 OFF)
  2) 선형/트라이오드: Vgs 크고 Vds 작음 → 저항처럼 동작 (스위치 ON)
  3) 포화(Saturation): Vgs 크고 Vds도 큼
     Id = (1/2) × μCox × (W/L) × (Vgs - Vth)²
     → Vds에 무관하게 전류 일정 → 전류원처럼 동작 → 증폭기로 사용!

  트랜스컨덕턴스 gm:
  gm = ∂Id/∂Vgs = μCox × (W/L) × (Vgs - Vth)
     = √(2 × μCox × (W/L) × Id)
  → gm이 클수록 게이트 전압 변화가 큰 드레인 전류 변화를 만듦
  → 증폭기 이득에 직결

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Common-Source 증폭기: 가장 기본적인 증폭기 ─────────────────────────────┐

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │          VDD                                                          │
  │           │                                                           │
  │          [Rd]  ← 드레인 저항 (이득 결정)                             │
  │           │                                                           │
  │           ├─────────────── Vout                                      │
  │           │                                                           │
  │  Vin ─────┤ G                                                        │
  │        NMOS│ D ──┘   (위에서 연결된 Rd로)                            │
  │           M1│                                                         │
  │           │ S                                                         │
  │           │                                                           │
  │          [Rs] ← 소스 저항 (동작점 안정화)                            │
  │           │                                                           │
  │          GND                                                          │
  │                                                                       │
  │  이득: Av = -gm × (Rd ‖ ro)                                          │
  │  ← 마이너스 부호 = 위상 반전 (입력↑ → 출력↓)                        │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  소신호 등가 회로로 이해:
  MOSFET을 소신호로 보면 → "전압 제어 전류원"
  게이트 전압 Vgs가 변하면 → 드레인에 gm × Vgs 만큼의 전류가 흐름
  이 전류가 Rd에 흐르면 전압 강하 → Vout = -gm × Vgs × Rd

  출력 저항 ro:
  포화 영역에서 Vds가 커지면 채널 길이가 줄어들며 전류가 미세하게 증가
  (Channel Length Modulation: 채널 길이 변조)
  ro = 1 / (λ × Id)   (λ: 채널 길이 변조 계수)
  → ro가 작으면 이득 저하 → Cascode 구조로 ro 향상

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Cascode 구조: 이득을 극한으로 올리는 법 ────────────────────────────────┐

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │   VDD ──── [Rd] ──── Vout                                            │
  │                │                                                      │
  │              M2 (Cascode MOSFET)  ← 이 트랜지스터가 핵심!           │
  │                │                                                      │
  │              Vbias ──┤G2           ← 바이어스 전압으로 고정          │
  │                                                                       │
  │              M1 (입력 MOSFET)                                         │
  │                │                                                      │
  │  Vin ─────────┤G1                                                    │
  │                │                                                      │
  │               GND                                                     │
  │                                                                       │
  │  이득: Av ≈ -gm × (ro_M1 × ro_M2 × gm_M2)    ← 엄청나게 큼!        │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  왜 M2를 추가하면 이득이 올라가나:
  - M1 드레인에서 보이는 저항이 M2 때문에 ro_M1 × (gm_M2 × ro_M2)로 증폭
  - M2가 M1 드레인 전압을 "클램핑"해서 채널 길이 변조 효과를 억제
  - → 출력 저항이 ro² 수준으로 커짐 → 이득도 그만큼 증가

  실제 장비 연계: OPAMP 내부의 이득단이 바로 Cascode 구조다.
  TIA 설계 시 OPAMP 내부에 Cascode가 들어가 있어서 높은 Aol 확보.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Pan-Tilt 모터 구동: MOSFET의 스위칭 응용 ───────────────────────────────┐

  Pan-Tilt 시스템에서 모터(BLDC 또는 DC 서보)를 돌리려면
  H-Bridge가 필요하다. H-Bridge는 MOSFET 4개로 구성된다.

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │                    H-Bridge (MOSFET 4개)                               │
  │                                                                         │
  │         VBat (배터리 전압, 예: 24V)                                    │
  │          │                 │                                           │
  │        [M1:PMOS]       [M2:PMOS]    ← High-Side FET                  │
  │          │                 │                                           │
  │          ├─── [모터] ──────┤                                           │
  │          │       ↑         │                                           │
  │        [M3:NMOS]  방향  [M4:NMOS]   ← Low-Side FET                   │
  │          │                 │                                           │
  │         GND               GND                                         │
  │                                                                         │
  │  정방향 회전: M1 ON + M4 ON  (M2,M3 OFF)  → 전류 왼→오              │
  │  역방향 회전: M2 ON + M3 ON  (M1,M4 OFF)  → 전류 오→왼              │
  │  제동(Brake): M3 ON + M4 ON               → 모터 단락, 빠른 정지     │
  │                                                                         │
  │  PWM 제어:                                                             │
  │  M1과 M4를 ON/OFF 반복 (주파수 20kHz)                                 │
  │  Duty Cycle 70% → 평균 전압 = 24V × 0.7 = 16.8V → 회전 속도 제어   │
  │                                                                         │
  │  MCU(STM32) → PWM 신호 → Gate Driver IC → M1~M4 게이트 구동          │
  │  Gate Driver가 필요한 이유:                                            │
  │  MCU 출력은 3.3V, 20mA → MOSFET 게이트를 빠르게 충전 불가            │
  │  Gate Driver는 수 A의 피크 전류로 게이트 급속 충방전 → 스위칭 손실 최소│
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  Dead-Time(데드타임):
  M1이 OFF되고 M3이 ON되는 사이에 둘 다 동시에 ON되는 순간이 생기면
  VBat → M1 → M3 → GND 경로로 단락(Shoot-Through) → 즉사.
  그래서 한 FET이 완전히 꺼진 후(약 100ns~1μs) 다른 FET을 켠다.
  이 시간이 Dead-Time. Gate Driver IC에서 자동 설정.

  └──────────────────────────────────────────────────────────────────────────┘

  A3.  LDO / 전원회로 안정화
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ 왜 전원을 안정화해야 하나 ──────────────────────────────────────────────┐

  예시: EO-IR 카메라 내부 구조

  드론 배터리는 22.2V (6S LiPo).
  카메라 내부 회로들이 필요한 전압은 각각 다르다:
  - InSb 센서 냉각용 TEC:  12V
  - ROIC (센서 읽기 회로): 3.3V, 1.8V
  - FPGA:                  1.0V (코어), 1.8V (IO), 3.3V (IO)
  - DDR 메모리:            1.1V
  - 아날로그 회로:         5V 또는 ±5V
  - 모터 드라이버:         24V (별도 공급)

  문제:
  배터리 전압은 충전 시 25.2V, 방전 시 18V까지 변한다 (±28% 변동).
  이 전압 변동이 그대로 회로에 들어가면 → 동작 불안정, 오차, 오동작.
  특히 ADC의 기준전압(Vref)이 흔들리면 → 측정값 전체가 틀어짐.
  → 전원 안정화(레귤레이터) 필수.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ LDO 동작 원리 ──────────────────────────────────────────────────────────┐

  LDO = Low Dropout Regulator (저드롭아웃 선형 레귤레이터)
  PMOS 트랜지스터를 가변 저항처럼 써서 입력전압에서 원하는 출력전압을 뽑음.

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │   Vin ──────────────┬──── [PMOS Pass Element] ──── Vout              │
  │                     │              ↑                  │              │
  │                     │        Gate 전압             [R1]              │
  │                     │              │                  │              │
  │                     │        [Error Amp]           [R2]              │
  │                     │        (+)      (-)             │              │
  │                     │        Vref   Vfb=Vout×R2/(R1+R2)             │
  │                     │                                 │              │
  │                    GND                               GND             │
  │                                                                       │
  │  동작:                                                                │
  │  1) Vout가 목표보다 낮으면 → Vfb < Vref → Error Amp 출력 낮아짐     │
  │     → PMOS Gate 전압 낮아짐 → PMOS 더 많이 켜짐 → Vout 올라감      │
  │  2) Vout가 목표보다 높으면 → 반대로 동작                             │
  │  → 음성 피드백(Negative Feedback)으로 항상 Vout 일정 유지            │
  │                                                                       │
  │  출력 전압 설정:  Vout = Vref × (1 + R1/R2)                          │
  │  예: Vref=0.8V, R1=150kΩ, R2=100kΩ → Vout = 0.8×(1+1.5) = 2.0V   │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  드롭아웃(Dropout) 전압:
  Vin과 Vout의 최소 차이. PMOS LDO는 Vdropout = Vgs_PMOS ≈ 0.3~0.6V
  즉, Vout = 3.3V를 내려면 Vin ≥ 3.6V 이상이어야 한다.
  그래서 "Low Dropout" — 이 여유 전압이 작을수록 좋다.
  드롭아웃이 클수록 = Vin - Vout 가 높아야 하므로 효율 저하.

  PSRR (Power Supply Rejection Ratio):
  Vin에서 발생한 노이즈가 Vout에 얼마나 새어 나오는지 비율 (dB).
  PSRR = 20 × log(ΔVin / ΔVout)  [dB]
  PSRR = 60dB → Vin에 1V 노이즈가 있어도 Vout에는 1mV만 나타남.
  아날로그 회로(ADC 기준전압, OPAMP 전원)에는 PSRR ≥ 70dB LDO 사용.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Buck Converter: 효율이 필요할 때 ──────────────────────────────────────┐

  LDO는 Vin - Vout 전압 차이만큼 열로 버린다.
  22V → 3.3V를 LDO로 만들면 효율 = 3.3/22 = 15% → 84.85%가 열!

  Buck Converter(강압형 스위칭 레귤레이터):
  MOSFET을 고속으로 ON/OFF해서 평균 전압을 만듦.
  Vout = Vin × D   (D = Duty Cycle, 0~1)
  효율 = 85~95% (열 손실 극히 적음)

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │   Vin ─── [SW: MOSFET] ─────────────── Vout                         │
  │                │                   │       │                         │
  │               PWM                 [L]    [C]  ← 출력 필터           │
  │                                    │       │                         │
  │            [다이오드]────────────── ┴ ─────┘                         │
  │            (또는 동기정류 MOSFET)                                    │
  │                │                                                      │
  │               GND                                                     │
  │                                                                       │
  │  동작:                                                                │
  │  SW ON  → 에너지가 L에 저장, Vout에 공급                             │
  │  SW OFF → L이 저장된 에너지를 다이오드 통해 Vout에 계속 공급        │
  │  → L과 C가 평균화 → 부드러운 DC 출력                                │
  │                                                                       │
  │  Vout 리플: ΔV = (Vin-Vout)×D / (L×fs×C)                           │
  │  fs = 스위칭 주파수 (100kHz~2MHz)                                    │
  │  fs 높을수록 L, C를 작게 쓸 수 있음 (소형화) 하지만 스위칭 손실↑   │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  └──────────────────────────────────────────────────────────────────────────┘

  A4.  ADC / DAC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ ADC: 아날로그를 디지털로 — 왜 필요하고 어떻게 동작하나 ────────────────┐

  ADC = Analog-to-Digital Converter
  현실의 물리량(온도, 빛, 거리, 각도)은 연속적인 아날로그 신호.
  MCU/FPGA/DSP는 0과 1의 디지털 세계. 이 둘을 이어주는 것이 ADC.

  N비트 ADC: 0~Vref 사이 전압을 2^N 개 구간으로 나눔.
  LSB(최소 구분 단위) = Vref / 2^N
  예: 12비트, Vref=3.3V → LSB = 3.3/4096 = 0.8mV
  즉, 0.8mV 차이까지 구분 가능.

  ADC 핵심 성능 지표:
  ─────────────────────────────────────────────────────────────────────────
  SNR   = 6.02×N + 1.76  [dB]  (이상적인 N비트 ADC의 신호대잡음비)
  ENOB  = (SINAD - 1.76) / 6.02  (실제 유효 비트 수: 이상값보다 항상 낮음)
  SFDR  = 제일 강한 스퍼리어스(spurious) 성분과 신호의 비율 [dBc]
  INL   = 이상적 전달함수에서의 최대 편차 [LSB]
  DNL   = 인접 코드 간격의 이상값(1LSB)에서의 편차 [LSB]
  ─────────────────────────────────────────────────────────────────────────

  ADC 종류와 실제 장비 연계:

  ┌───────────┬──────────┬──────────┬────────────────────────────────────┐
  │ 방식      │ 속도     │ 해상도   │ 실제 사용처                        │
  ├───────────┼──────────┼──────────┼────────────────────────────────────┤
  │ Flash     │ GS/s     │ 6~8비트  │ 레이더 중간주파수(IF) 디지털화    │
  │ SAR       │ MS/s     │ 10~18비트│ IMU 센서, 배터리 전압 측정        │
  │ Sigma-Del.│ kS/s     │ 16~24비트│ ECG, 정밀 온도, 오디오             │
  │ Pipeline  │ 100MS/s  │ 12~16비트│ EO-IR 영상 ROIC 내부              │
  └───────────┴──────────┴──────────┴────────────────────────────────────┘

  EO-IR 카메라 ROIC 안의 ADC:
  각 픽셀(또는 열 단위)에 ADC가 있어서 광전류 → 디지털값 변환.
  14비트 Pipeline ADC 사용 → 초당 수백 프레임 × 픽셀 수만큼 변환.
  SNR = 6.02×14 + 1.76 = 86.0dB (이상적), 실제 ENOB ≈ 12~13비트.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ 나이퀴스트 정리와 앤티앨리어싱 필터 ───────────────────────────────────┐

  나이퀴스트(Nyquist) 정리:
  샘플링 주파수 fs로 신호를 제대로 복원하려면 fs ≥ 2 × fmax 필요.
  즉, 1kHz 신호를 측정하려면 최소 2kHz 이상으로 샘플링해야 함.

  앨리어싱(Aliasing):
  fs보다 높은 주파수 성분이 신호에 있으면 → 다른 주파수로 잘못 해석됨.
  예: fs=10kHz로 샘플링할 때 8kHz 노이즈 → 2kHz 가짜 신호로 나타남.

  해결책: Anti-Aliasing 필터 (ADC 앞에 LPF 삽입)
  → fs/2 보다 높은 주파수를 ADC 앞에서 미리 제거.

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │   아날로그 신호                                                        │
  │   (노이즈 포함)  →  [LPF Anti-Aliasing]  →  [ADC]  →  디지털        │
  │                       fc = fs/2 이하              ↑                  │
  │                                             샘플링 주파수 fs         │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  EO-IR 카메라에서 앤티앨리어싱:
  FPA(Focal Plane Array)의 픽셀 간격(픽셀 피치)이 나이퀴스트 기준.
  광학계의 MTF(변조전달함수)가 픽셀 피치에 맞는 공간 주파수 성분만
  통과시키도록 광학 설계 → 광학 앤티앨리어싱 필터 역할.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ DAC: 디지털을 아날로그로 — Pan-Tilt 속도 명령 ─────────────────────────┐

  DAC = Digital-to-Analog Converter
  MCU의 디지털 명령값 → 아날로그 전압 → 모터 드라이버 기준 전압으로 사용.

  R-2R Ladder DAC (가장 단순한 구조):
  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │   D3 (MSB)   D2    D1    D0 (LSB)                                    │
  │    │          │     │     │                                           │
  │   [2R]       [2R]  [2R]  [2R]                                        │
  │    │          │     │     │                                           │
  │    ├──[R]──── ┤     │     │                                           │
  │    │          ├──[R]┤     │                                           │
  │    │          │     ├──[R]┤                                           │
  │    │          │     │     │                                           │
  │   Vout ──────────────────┘                                            │
  │                                                                       │
  │  각 비트가 Vref의 1/2, 1/4, 1/8, 1/16 씩 기여                       │
  │  D3=1,D2=0,D1=1,D0=0 → Vout = Vref × (8+0+2+0)/16 = 0.625×Vref    │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  Pan-Tilt 속도 제어에서 DAC의 역할:
  MCU의 PID 연산 결과(디지털 정수) → DAC → 아날로그 전압
  → 모터 드라이버의 전류 제한 핀(VREF)에 인가 → 모터 전류 제어
  → 전류 = 토크 = 회전 속도 제어

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ RTL이 뭔가 — 하드웨어를 코드로 기술하는 것 ─────────────────────────────┐

  RTL = Register Transfer Level
  하드웨어 회로를 "클록마다 레지스터 간에 데이터가 어떻게 전달되는지"로
  기술하는 추상화 수준. Verilog 또는 VHDL로 작성한다.

  소프트웨어 코드와 결정적 차이:
  - 소프트웨어: 명령이 순차적으로 실행 (한 번에 하나씩)
  - RTL/하드웨어: 모든 블록이 동시에 병렬로 동작
  → always 블록 여러 개가 있으면 모두 동시에 실행됨

  Blocking(=) vs Non-Blocking(<=) 차이 — 가장 많이 헷갈리는 부분:

  Blocking (=): 그 줄이 실행되면 즉시 반영 (순차적)
  Non-Blocking (<=): 클록 엣지 끝날 때 한꺼번에 반영 (동시)

  always @(posedge clk) 안에서는 반드시 <= 써야 한다!
  = 를 쓰면 시뮬레이션과 합성 결과가 달라지는 재앙이 발생.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ 조합 논리 vs 순차 논리 ─────────────────────────────────────────────────┐

  조합 논리 (Combinational Logic):
  - 클록 없이 입력 → 즉시 출력
  - 메모리 없음, 현재 입력만으로 출력 결정
  - Verilog: always @(*) 또는 assign 사용
  - 예: 덧셈기, MUX, 디코더, 주소 디코딩

  순차 논리 (Sequential Logic):
  - 클록 엣지에서만 출력 변경
  - 내부 상태(레지스터) 존재 → 이전 값을 기억
  - Verilog: always @(posedge clk) 사용
  - 예: 카운터, FSM, FIFO, 파이프라인 레지스터

  FSM (Finite State Machine): 순차 논리의 핵심
  ─────────────────────────────────────────────────────────────────────────
  현재 상태 + 입력 → 다음 상태 + 출력을 정의하는 표/다이어그램/코드.

  Pan-Tilt 제어기의 FSM 예시:

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │    IDLE ──── 목표위치 수신 ──── MOVING ──── 목표도달 ──── HOLD      │
  │      │                             │                        │        │
  │      └──── 비상정지 ────────────── ┴──── 비상정지 ──── EMERGENCY   │
  │                                                                       │
  │  IDLE   : 모터 정지, 엔코더 위치만 모니터링                          │
  │  MOVING : PID 계산, PWM 출력, 위치 오차 지속 체크                   │
  │  HOLD   : 목표 위치 유지, 외란 보정 (바람 등)                        │
  │  EMERG  : 즉시 모터 OFF, 이상 로그 저장, 상위에 보고                │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  ┌ Timing: Setup/Hold Time — 타이밍 위반이 왜 위험한가 ───────────────────┐

  플립플롭(FF, D Flip-Flop)은 클록 엣지에서 D 입력을 Q 출력으로 복사.
  단, 두 가지 시간 조건을 만족해야 한다:

  Setup Time (Tsu): 클록 엣지 전 D가 안정돼야 하는 시간
  Hold Time  (Th):  클록 엣지 후 D를 유지해야 하는 시간

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │   D  ────────────XXXXX──────────────────                             │
  │                  ↑   ↑                                               │
  │               Tsu  Th  (이 구간에 D가 변하면 안 됨)                 │
  │                    ↑                                                  │
  │   CLK ─────────────/──────────────── (클록 상승 엣지)                │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  타이밍 위반(Timing Violation) 결과:
  Setup 위반 → FF가 잘못된 값을 캡처 (메타스태빌리티)
  Hold 위반  → FF 출력이 글리치(Glitch) 발생
  → 시스템이 간헐적으로 오동작 → 재현하기 어려운 최악의 버그

  STA (Static Timing Analysis):
  모든 경로에서 Setup/Hold을 수학적으로 계산해서 마진 확인.
  합성 도구(Design Compiler)와 P&R 도구(ICC2)가 자동 수행.
  "Slack"이 음수면 → 위반 → 타이밍 클로저(Timing Closure) 실패.

  ┌ UART, SPI, I2C: RTL로 구현하는 통신 프로토콜 ──────────────────────────┐

  Pan-Tilt 시스템에서 MCU ↔ FPGA ↔ 상위 시스템 간 통신:

  UART (Universal Async Receiver Transmitter):
  - 클록 선 없음, 시작/정지 비트로 동기화
  - 115200 baud = 초당 115,200비트
  - 디버그 콘솔, 간단한 명령 전송에 사용
  - RS-232, RS-422, RS-485 물리층과 조합

  SPI (Serial Peripheral Interface):
  - 마스터가 클록 공급, 전이중(Full Duplex)
  - MOSI(데이터↓), MISO(데이터↑), SCK(클록), CS(선택)
  - IMU(가속도계/자이로), ADC, Flash 메모리 연결에 사용
  - 최대 수십 MHz → 빠른 센서 데이터 수집에 적합

  I2C (Inter-Integrated Circuit):
  - 2선(SDA, SCL), 다중 슬레이브 가능
  - 주소로 디바이스 선택 (7비트 주소 = 최대 128개 장치)
  - 온도 센서, EEPROM, PMIC 설정 레지스터 접근에 사용
  - 최대 1MHz (Fast-Mode Plus)

  D2.  FPGA 내부 구조 및 응용
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ FPGA가 MCU/ASIC과 뭐가 다른가 ─────────────────────────────────────────┐

  MCU(STM32 등):
  - 정해진 회로(CPU 코어)가 있고, 소프트웨어로 기능 정의
  - 명령 실행 속도: 수십~수백 MHz, 명령은 순차 실행
  - 고정된 주변기기(UART, SPI, ADC 등)

  FPGA(Xilinx Artix-7 등):
  - 아무 회로나 구현 가능 — 내부에 수만~수백만 개의 LUT이 있음
  - 하드웨어 수준 병렬 처리: 수천 개 동작 동시 실행
  - 최대 수백 MHz 클록으로 병렬 처리 → 초고속 신호처리

  ASIC(Application Specific IC):
  - 특정 기능만 하는 칩을 실리콘에 새겨서 대량생산
  - 최고 속도/전력 효율, 하지만 설계비/기간 막대
  - 한 번 만들면 수정 불가

  FPGA는 "검증용, 소량생산용 ASIC 대체, 또는 ASIC으론 못 하는 유연성 필요 시"

  LUT (Look-Up Table):
  6입력 LUT = 64비트 진리표를 저장하는 SRAM.
  어떤 6입력 조합 논리도 구현 가능.
  예: A AND B OR C → LUT 진리표에 결과값 저장.
  합성 도구가 Verilog를 읽고 자동으로 LUT 진리표 설정.

  DSP 블록:
  곱셈+누산(MAC: Multiply-Accumulate) 전용 하드와이어드 회로.
  FIR 필터, FFT, PID 연산 등 수학 집약적 연산에 사용.
  LUT으로 곱셈기 만들면 수백 개 LUT 소모, DSP 블록이면 1개로 해결.

  CMT (Clock Management Tile):
  PLL + MMCM 포함. 외부 클록(24MHz 수정발진자)을 받아서
  내부에서 여러 주파수/위상의 클록 생성.
  예: 24MHz 입력 → 200MHz(DDR 클록), 100MHz(로직), 25MHz(이더넷) 동시 생성.

  ┌ 합성이란: RTL → 실제 게이트로 변환 ────────────────────────────────────┐

  Verilog/VHDL로 쓴 코드는 "동작 기술"이다.
  이것을 실제 칩에 새길 수 있는 물리적 게이트 연결로 바꾸는 것이 합성.

  합성 과정:
  1) 파싱(Parsing): RTL 코드 구조 분석
  2) 정교화(Elaboration): 모듈 계층 구조 전개
  3) 최적화(Optimization): 불필요한 논리 제거, 공통 부분 공유
  4) 기술 매핑(Technology Mapping): 라이브러리 셀(AND, OR, FF 등)로 치환
  → 출력: Gate-Level Netlist (.v 파일, 게이트와 연결 목록)

  합성 도구: Synopsys Design Compiler (업계 표준), Yosys (오픈소스)
  FPGA 합성: Vivado (Xilinx), Quartus (Intel/Altera) 내장

  CTS(Clock Tree Synthesis) 중요성:
  칩에 수백만 개의 FF가 있을 때, 클록이 어떤 FF에는 1.0ns, 다른 FF에는
  1.5ns 뒤에 도달하면 → 0.5ns 클록 스큐(Clock Skew) 발생.
  → Setup/Hold 타이밍 분석에서 이 스큐가 마진을 깎아먹음.
  → CTS: 버퍼 트리를 설계해서 모든 FF에 동일 지연으로 클록 분배.

  └──────────────────────────────────────────────────────────────────────────┘

  D4.  DFT (Design for Testability)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ 왜 테스트가 어려운가 ────────────────────────────────────────────────────┐

  제조된 칩이 "도면대로 만들어졌는지" 확인하려면 내부를 봐야 하는데,
  완성된 칩은 불투명한 패키지에 싸여 있고 수천만 개 노드 중
  외부에서 직접 접근 가능한 핀은 수백 개뿐.

  예: 내부 어딘가의 배선이 GND에 달라붙어(Stuck-at-0) 항상 0이면
  그 노드를 1로 만들어 보고, 1이 출력까지 전파되는지 확인해야 탐지.
  → 이를 위해 설계 단계부터 테스트를 위한 구조를 심어놓는 것이 DFT.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Scan Chain: 모든 FF를 이어서 들여다보는 방법 ───────────────────────────┐

  Scan Chain의 아이디어:
  - 칩 내부의 모든 FF에 2:1 MUX를 추가
  - 정상 모드: D 입력이 정상 회로 신호
  - 스캔 모드: D 입력이 이전 FF의 Q (직렬로 이어짐)
  - 이러면 모든 FF가 하나의 긴 시프트 레지스터가 됨

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  정상 모드:                                                           │
  │  [조합논리] → [FF1] → [조합논리] → [FF2] → ... → 출력               │
  │                                                                       │
  │  스캔 모드:                                                           │
  │  SCAN_IN → [FF1] → [FF2] → [FF3] → ... → [FFn] → SCAN_OUT          │
  │                                                                       │
  │  FF 내부 (Scan FF):                                                   │
  │                                                                       │
  │  Scan_In ──┐                                                          │
  │            ├──[MUX]──→ D ──[FF]──→ Q                                 │
  │  D_norm  ──┘   ↑                                                      │
  │               SE (Scan Enable: 0=정상, 1=스캔)                        │
  │                                                                       │
  │  테스트 순서:                                                         │
  │  1) SE=1 (스캔 모드)                                                  │
  │  2) SCAN_IN으로 테스트 패턴을 시프트로 집어넣음 (N 클록)             │
  │  3) SE=0 (정상 모드)로 전환 후 1 클록 동작 (Capture)                 │
  │  4) SE=1 복귀 후 FF 내용을 SCAN_OUT으로 읽어냄                       │
  │  5) 기대값과 비교 → 불일치 = 결함 있음                               │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  M1.  SAR ADC 구조
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ SAR ADC: 이진 탐색으로 전압을 맞추는 ADC ──────────────────────────────┐

  SAR = Successive Approximation Register (순차 근사 레지스터)

  동작 원리 — "업다운 게임":
  모르는 값 X를 맞추는 게임. Vref = 3.3V, 12비트 ADC.

  Step 1: DAC을 Vref/2 = 1.65V로 설정
          X > 1.65V? → YES → MSB = 1 (이 절반 이상임)
  Step 2: DAC을 1.65 + Vref/4 = 2.475V로 설정
          X > 2.475V? → NO  → 다음 비트 = 0
  Step 3: DAC을 1.65 + Vref/8 = 2.0625V로 설정
          X > 2.0625V? → YES → 다음 비트 = 1
  ...12번 반복 → 12비트 결과 완성.

  이것이 이진 탐색(Binary Search). N비트를 결정하는 데 N클록만 필요.
  Flash ADC는 2^N개 비교기 필요, SAR은 비교기 1개면 충분 → 초저전력.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ SAR ADC 내부 회로 구조 ─────────────────────────────────────────────────┐

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │   Vin ─────[Bootstrap SW]─────┬──[S/H 커패시터]                        │
  │                               │                                         │
  │                             (Vx)                                        │
  │                               │                                         │
  │                         [Comparator]                                    │
  │                          (+)     (-)                                    │
  │                          Vx     VDAC                                   │
  │                               │                                         │
  │                          [SAR Logic]  ←──────────────────┐             │
  │                               │                          │             │
  │                          [C-DAC]─────→ VDAC             │             │
  │                      (이진가중 커패시터)      피드백      │             │
  │                               │                          │             │
  │                          [결과 레지스터]─────────────── Dout           │
  │                                                                         │
  │  Bootstrap Switch:                                                      │
  │  입력 신호가 0~Vref 전체를 스위치로 연결할 때, 스위치 저항이           │
  │  신호 레벨에 따라 달라지면(비선형) → 왜곡 발생.                       │
  │  Bootstrap SW는 게이트-소스 전압을 항상 일정하게 유지해서             │
  │  신호 레벨에 무관한 일정 저항 → 선형성 확보.                          │
  │                                                                         │
  │  C-DAC (Capacitive DAC):                                               │
  │  ┌──┬──┬──┬──┬──┐  각 커패시터는 이진 가중 (C, 2C, 4C, 8C...)       │
  │  │C │2C│4C│8C│16C│  D0=1이면 Vref/2 기여, D1=1이면 Vref/4...         │
  │  └──┴──┴──┴──┴──┘                                                     │
  │  D4 D3 D2 D1 D0                                                        │
  │                                                                         │
  │  커패시터 미스매치:                                                     │
  │  4C 커패시터가 실제로 3.98C라면 → 코드 1000에서 오차 → INL 열화      │
  │  → 레이아웃에서 Common-Centroid 배치로 미스매치 최소화               │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  드론 배터리 모니터에서 SAR ADC:
  배터리 전압(0~25.2V)을 분압기로 0~3.3V 범위로 낮춘 후
  MCU 내장 12비트 SAR ADC로 측정.
  LSB = 3.3/4096 = 0.8mV → 분압 비율 고려 시 배터리 측정 분해능 ≈ 6mV.
  초당 수백 회 측정 후 평균 → 전압 정확도 향상.

  M2.  PLL / Jitter
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ PLL: 주파수를 잠그는 회로 ──────────────────────────────────────────────┐

  PLL = Phase-Locked Loop (위상 고정 루프)

  왜 필요한가:
  - FPGA는 내부 동작에 200MHz 클록이 필요하지만
    외부 수정발진자는 보통 25MHz (정밀하고 저렴한 주파수).
  - PLL이 25MHz를 받아서 200MHz로 체배.
  - 드론 레이더: VCO(발진기)가 77GHz를 만드는데,
    기준 발진기(100MHz)의 위상에 PLL로 고정 → 안정적인 77GHz 생성.

  PLL 동작 원리:

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  fref ──→ [PFD] ──→ [CP] ──→ [Loop Filter] ──→ [VCO] ──→ fout      │
  │  (기준)    │           │           │               │                  │
  │            │        전류출력    저주파통과        주파수              │
  │            │          Iup/Idn                      │                  │
  │            └────────────────── [÷N] ←──────────────┘                 │
  │                                (분주기)                               │
  │                                                                       │
  │  fout = N × fref                                                      │
  │  예: fref=25MHz, N=8 → fout=200MHz                                   │
  │                                                                       │
  │  각 블록의 역할:                                                      │
  │                                                                       │
  │  PFD (Phase-Frequency Detector):                                      │
  │  기준 클록과 피드백 클록의 위상/주파수 차이를 검출.                  │
  │  피드백이 느리면 → UP 펄스 출력                                       │
  │  피드백이 빠르면 → DN 펄스 출력                                       │
  │                                                                       │
  │  CP (Charge Pump):                                                    │
  │  UP 펄스 → 전류 Icp를 루프 필터로 공급 → 전압 올라감                │
  │  DN 펄스 → 전류 Icp를 루프 필터에서 뽑음 → 전압 내려감              │
  │                                                                       │
  │  Loop Filter:                                                         │
  │  고주파 잡음 제거 (R-C 필터). 루프 대역폭 결정.                      │
  │  BW ≈ fref/10  (경험적 설계 가이드)                                  │
  │                                                                       │
  │  VCO (Voltage-Controlled Oscillator):                                 │
  │  제어 전압이 높으면 → 주파수 높아짐                                   │
  │  Kvco = Δf/ΔV  [MHz/V]  (VCO 감도)                                  │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  PLL 잠금(Lock) 과정:
  초기에 fout와 fref의 주파수/위상이 다름.
  PFD가 오차 검출 → CP가 전류 공급 → VCO 주파수 변화 → 점점 일치.
  완전히 일치하면 "Lock" 상태 — 이후 오차가 생기면 루프가 자동 보정.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Jitter: 클록이 정확하지 않을 때 생기는 문제 ────────────────────────────┐

  이상적인 클록은 정확히 T_clk마다 엣지가 온다.
  실제 클록은 매번 조금씩 타이밍이 달라진다 — 이 편차가 Jitter.

  Jitter 종류:
  - Period Jitter: 한 사이클의 주기 변동
  - Cycle-to-Cycle Jitter: 연속 사이클 간 주기 차이
  - Long-Term Jitter (Phase Noise): 주파수 영역으로 표현

  Jitter가 왜 문제인가:
  1) ADC 샘플링: 샘플링 순간의 불확실성 → SNR 열화
     SNR_jitter = -20 × log₁₀(2π × f_input × t_jitter)
     예: 100MHz 신호, 1ps RMS jitter → SNR = -20×log(2π×10⁸×10⁻¹²)
                                            = -20×log(6.28×10⁻⁴) = 64dB

  2) DDR 메모리: 클록 jitter → 데이터 캡처 타이밍 오류 → 메모리 오류

  3) 레이더: 위상 잡음이 도플러 필터를 오염 → 저속 표적 탐지 불가

  Phase Noise 측정:
  스펙트럼 분석기로 VCO 출력을 보면 반송파 옆에 스커트(Skirt) 형태의
  노이즈 바닥이 보임. 단위: dBc/Hz (반송파 대비, 특정 오프셋 주파수에서).
  예: -90 dBc/Hz @ 100kHz → 반송파에서 100kHz 떨어진 곳의 노이즈 밀도.

  └──────────────────────────────────────────────────────────────────────────┘


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  M3.  Bode Plot / FFT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ Bode Plot: 회로의 주파수 응답을 그림으로 ──────────────────────────────┐

  어떤 회로에 다양한 주파수의 정현파를 넣으면
  출력의 크기(이득)와 위상이 주파수마다 다르다.
  이 관계를 주파수에 대해 그린 것이 Bode Plot.

  x축: 주파수 (로그 스케일, Hz)
  y축 상단: 이득 (dB = 20×log|H(jω)|)
  y축 하단: 위상 (degree)

  극점(Pole)과 영점(Zero):
  - 극점: 이득이 -20dB/dec로 감소하기 시작하는 주파수 + 위상 -90° 기여
  - 영점: 이득이 +20dB/dec로 증가 + 위상 +90° 기여

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  dB                                                                   │
  │   40 ├──────────────╲                                                 │
  │      │               ╲  ← -20dB/dec (극점 1개)                       │
  │   20 ├────────────────╲                                               │
  │      │          -3dB→  ╲──────────────────────────                   │
  │    0 ├─────────────────────────────────────────── Hz                  │
  │         DC      fp (극점 주파수)    고주파                             │
  │                                                                       │
  │  위상                                                                 │
  │    0° ├──────────────╲                                                │
  │      │                ╲                                               │
  │  -45° ├────────────────╲← fp에서 정확히 -45°                         │
  │      │                  ╲                                             │
  │  -90° ├──────────────────────────────────────────                    │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  실제 장비 연계: LDO의 PSRR Bode Plot

  LDO는 저주파에서 PSRR이 높고(전원 노이즈 잘 제거),
  고주파로 갈수록 PSRR이 낮아진다(루프 이득 감소로 보상 못함).
  → FPGA 스위칭 노이즈(수백 MHz)가 아날로그 전원을 오염시키는 이유.
  → 해결: LDO + 추가 LC 필터 조합.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ FFT: 시간 신호를 주파수로 분해 ────────────────────────────────────────┐

  FFT = Fast Fourier Transform
  어떤 복잡한 신호도 여러 주파수의 정현파의 합으로 표현 가능 (푸리에 정리).
  FFT는 이 성분별 주파수/크기/위상을 빠르게 계산하는 알고리즘.

  FMCW 레이더에서 FFT의 핵심 역할:

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │  레이더 송신: 시간에 따라 주파수가 선형 증가하는 처프(Chirp) 신호     │
  │                                                                         │
  │  f↑                                                                    │
  │    │  /  /  /  /  /  /   ← 처프 신호 (주파수가 올라갔다 다시 내려옴) │
  │    │ /  /  /  /  /  /                                                  │
  │    └──────────────────── t                                             │
  │                                                                         │
  │  표적에 반사된 수신 신호: 시간 지연 τ = 2R/c (R=거리, c=빛속도)      │
  │                                                                         │
  │  f↑                                                                    │
  │    │   /  /  /  /  /  /   ← 수신 신호 (τ 만큼 지연됨)               │
  │    │ _/  /  /  /  /  /                                                 │
  │    └──────────────────── t                                             │
  │                                                                         │
  │  Mixer로 두 신호를 곱하면 → 비트 주파수 fb = (Δf/T) × τ             │
  │  fb = (대역폭/스윕시간) × 왕복지연                                   │
  │  → fb가 크면 멀리 있는 표적                                           │
  │                                                                         │
  │  비트 신호에 FFT → 주파수 스펙트럼 → 피크 위치 = 거리 정보          │
  │                                                                         │
  │  dB│                                                                   │
  │    │       │← 피크: fb = 5kHz → R = 5kHz×c×T/(2×Δf) 계산           │
  │    │       │                                                           │
  │    └───────────────────────── Hz                                       │
  │        0   5k  10k  15k                                                │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  2D FFT (Range-Doppler 처리):
  여러 처프를 연속 송신 후 각 거리 셀에서 시간에 따른 위상 변화를 FFT
  → 도플러 주파수 → 표적 속도 추출.
  → Range-Doppler 맵: x축=거리, y축=속도, 밝기=신호 세기

  ┌ NUC (Non-Uniformity Correction): EO-IR 카메라의 핵심 보정 ────────────┐

  NUC 2점 보정 원리:
  각 픽셀의 응답이 선형이라고 가정: DN = G × T + O
  (DN = 디지털 출력값, G = 이득, O = 오프셋, T = 표적 온도)

  두 가지 알려진 온도에서 측정하면 G와 O를 구할 수 있다.

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  보정 방법:                                                           │
  │                                                                       │
  │  ① 균일 온도 T1의 블랙바디 앞에서 모든 픽셀 DN1[x,y] 수집           │
  │  ② 균일 온도 T2의 블랙바디 앞에서 모든 픽셀 DN2[x,y] 수집           │
  │                                                                       │
  │  각 픽셀(x,y)에 대해:                                                │
  │  G[x,y]  = (T2 - T1) / (DN2[x,y] - DN1[x,y])   [온도/DN 변환계수] │
  │  O[x,y]  = T1 - DN1[x,y] × G[x,y]               [온도 오프셋]      │
  │                                                                       │
  │  실제 촬영 시:                                                        │
  │  T_corrected[x,y] = G[x,y] × DN_raw[x,y] + O[x,y]                  │
  │                                                                       │
  │  FPGA에서 구현:                                                       │
  │  - G, O 계수를 BRAM에 저장 (픽셀당 2개 값, 총 수십만 × 2 값)       │
  │  - 매 프레임 매 픽셀마다 곱셈+덧셈 한 번씩 수행                     │
  │  - DSP 블록 사용 → 파이프라인으로 픽셀 처리량 유지                  │
  │                                                                       │
  │  언제 다시 NUC하나:                                                   │
  │  - 카메라 온도가 크게 변할 때 (ROIC 자체 온도 변화 → 오프셋 변화)  │
  │  - FLIR G5-550HD: 셔터(균일 온도 판)를 자동으로 닫아서 매 분 NUC   │
  │  - 셔터가 닫히는 순간 = 영상이 잠깐 끊기는 현상이 바로 이것         │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  ┌ 노이즈 종류 완전 정리 ──────────────────────────────────────────────────┐

  1) Thermal (Johnson) Noise:
     도체 내 전자의 열운동으로 발생. 저항 R에서 항상 존재.
     Vn = √(4kTRB)  [V rms]
     k=1.38×10⁻²³ J/K, T=절대온도, B=대역폭
     → R을 줄이거나 BW를 줄이면 감소. 온도 낮추면 감소(InSb 냉각 이유!)

  2) Shot Noise:
     전류가 양자화된 전하(전자)의 흐름이라 생기는 통계적 잡음.
     In = √(2qIB)  [A rms]
     q=1.6×10⁻¹⁹ C, I=평균 전류, B=대역폭
     → 포토다이오드의 광전류, 역방향 바이어스 전류에서 발생.

  3) Flicker (1/f) Noise:
     반도체 표면의 트랩(결함)으로 인한 저주파 잡음.
     전력 스펙트럼 ∝ 1/f → 주파수 낮을수록 커짐.
     ECG(0.1~150Hz), 오디오(20Hz~20kHz)처럼 저주파 측정 시 심각.
     MOSFET이 BJT보다 1/f 노이즈 심함 (표면 도체이므로).

  4) Quantization Noise:
     ADC에서 연속값을 이산값으로 반올림할 때 생기는 오차.
     Vnq = LSB / √12  [V rms]
     → N비트 ADC, 해상도 높이면 감소.

  TIA 노이즈 버짓 (EO-IR 카메라 전단 예시):
  ─────────────────────────────────────────────────────────────────────────
  Rf = 1MΩ, BW = 100kHz, T = 300K (상온), OPAMP In = 5fA/√Hz

  Thermal: √(4 × 1.38e-23 × 300 × 1e6 × 1e5) = 40.6 μVrms
  OPAMP 전류: 5e-15 × 1e6 × √(1e5)             = 1.58 μVrms
  합산(RSS): √(40.6² + 1.58²)                   ≈ 40.6 μVrms
  → SNR = Vsignal / Vnoise 로 결정
  ─────────────────────────────────────────────────────────────────────────

  ┌ PCB가 그냥 "구리선이 있는 판"이 아닌 이유 ─────────────────────────────┐

  신호 주파수가 MHz → GHz로 올라가면
  PCB의 구리 배선이 단순한 도선이 아닌 "전송선로(Transmission Line)"로 동작.

  전송선로는:
  - 분산 인덕턴스 L'와 커패시턴스 C'를 가짐
  - 특성 임피던스: Z0 = √(L'/C')  [Ω]
  - Z0가 일정해야 신호가 반사 없이 전달
  - Z0는 배선 폭(W), 절연재 두께(H), 절연재 유전율(Er)에 의해 결정

  이 Z0를 맞추기 위해 PCB 층 구조(Stackup)를 설계하는 것.
  층이 많을수록 더 많은 신호를, 더 깨끗하게 배선할 수 있다.

  ┌ 반사(Reflection): 임피던스 불연속 지점에서 신호가 튀는 현상 ──────────┐

  고속 신호가 전송선로를 타고 가다가 임피던스가 다른 곳을 만나면
  일부 신호가 되튀어 나온다. 마치 빛이 다른 매질에서 굴절/반사하듯.

  반사 계수: Γ = (ZL - Z0) / (ZL + Z0)
  ZL = 부하 임피던스, Z0 = 전송선로 특성 임피던스

  ZL = Z0이면 Γ = 0 → 반사 없음 (완전 정합)
  ZL = 0 (단락)이면 Γ = -1 → 전압 반전 반사
  ZL = ∞ (개방)이면 Γ = +1 → 전압 두 배 반사

  DDR4 데이터 라인에서 반사가 발생하면:
  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  이상적인 신호:                                                        │
  │  ─────────────────────────────────────────────────────                │
  │  HIGH                                                                  │
  │  ─────────────────────────────────────────────────────                │
  │  LOW                                                                   │
  │                                                                        │
  │  반사가 있는 실제 신호:                                               │
  │  ────────╲                                                            │
  │  HIGH      ╲   ← 언더슈트 (반사파와 간섭)                            │
  │  ────────── ╲──────────────────────────────                           │
  │             ╱                                                          │
  │  LOW ──────╱   ← 링잉(Ringing)                                       │
  │                                                                        │
  │  → 수신기가 HIGH인지 LOW인지 판단 기준(문턱값)에 걸쳐서 오류 발생   │

  종단 저항 (Termination):
  신호 끝에 Z0와 같은 저항(예: 50Ω)을 달면 반사 없음.
  - 소스 종단: 드라이버 출력에 직렬 저항 (Rs = Z0 - Rout_driver)
  - 병렬 종단: 수신단에 Z0 저항을 VTT에 연결
  DDR4는 On-Die Termination (ODT): DRAM 칩 내부에 종단 회로 내장.

  ┌ Power Integrity: 전원 노이즈가 신호에 미치는 영향 ─────────────────────┐

  FPGA 내부 수백만 개 로직이 클록 엣지에서 동시에 전환(스위칭).
  각 스위칭 시 전원에서 순간적으로 큰 전류 소모.
  → 전원 라인의 인덕턴스(PCB 배선, 비아, 패드 등)에 전압 강하 발생.
  ΔV = L × dI/dt
  → 이것이 Ground Bounce 또는 SSO(Simultaneous Switching Output) 잡음.

  PDN (Power Delivery Network) 설계:
  목표: 어떤 주파수에서도 PDN 임피던스를 목표값 이하로 유지.
  Ztarget = ΔV_허용 / ΔI_최대
  예: 1.0V 전원에서 리플 1% 허용, 순간 전류 변화 5A
  → Ztarget = 0.01V / 5A = 2mΩ

  디커플링 커패시터 역할:
  배터리/레귤레이터는 MHz 이상 고주파 전류를 빠르게 공급 못함.
  → IC 근처에 커패시터를 두어 순간 전류를 "로컬 저장소"에서 공급.
  - 100nF: 10~100MHz 디커플링 (ESL 작은 MLCC)
  - 10μF: 1~10MHz 디커플링
  - 100μF: 100kHz~1MHz 디커플링 (벌크 커패시터)
  각 주파수 범위가 다른 커패시터를 조합해서 광대역 PDN 구성.

  └──────────────────────────────────────────────────────────────────────────┘


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  P3.  Crosstalk / EMI / EMC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ Crosstalk: 옆 신호가 내 신호에 간섭하는 현상 ──────────────────────────┐

  PCB에 두 배선이 나란히 지나가면 전자기 결합이 발생한다.
  Aggressor(가해자 라인)의 신호가 변할 때
  Victim(피해자 라인)에 원하지 않는 신호가 유도된다.

  결합 메커니즘 2가지:
  ① 용량성 결합 (Capacitive Coupling):
     두 배선 사이의 기생 커패시터 Cm을 통해 전류가 흐름.
     ic = Cm × dV/dt  (신호 변화율이 클수록 간섭 심함)

  ② 유도성 결합 (Inductive Coupling):
     두 배선 사이의 상호 인덕턴스 Lm을 통해 전압 유도.
     v = Lm × dI/dt

  NEXT vs FEXT:
  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  Aggressor:  ──────────────────────────────────→ 신호 진행 방향      │
  │              ↑ 시작점                            ↑ 끝점              │
  │             NEXT                                FEXT                  │
  │              ↓                                   ↓                   │
  │  Victim:   ←─────────────────────────────────────                    │
  │                                                                       │
  │  NEXT (Near-End Crosstalk):                                           │
  │  - Aggressor 시작점 쪽에서 Victim이 받는 간섭                        │
  │  - 용량성 + 유도성 결합이 더해짐                                     │
  │  - 보통 크로스토크 분석의 주요 관심 대상                             │
  │                                                                       │
  │  FEXT (Far-End Crosstalk):                                            │
  │  - Aggressor 끝점 쪽에서 Victim이 받는 간섭                          │
  │  - 용량성 - 유도성 결합이 부분 상쇄 (마이크로스트립 경우)           │
  │  - 동방향 전파이므로 신호와 같이 이동, 펄스 폭 늘어남               │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  크로스토크 억제 방법:
  1) 간격 넓히기: 배선 간격 D를 넓히면 Cm, Lm 급감. 3W 규칙이 경험적 지침.
     3W 규칙: 배선 중심 간 간격 ≥ 3 × 배선 폭
     ← 이 거리 이상이면 크로스토크가 충분히 작아짐.

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  3W 규칙 도해:                                                        │
  │                                                                       │
  │  ←W→     ← 2W →    ←W→                                               │
  │  ┌───┐             ┌───┐                                              │
  │  │ A │             │ B │    간격 = 2W → 중심 간 거리 = 3W ✓          │
  │  └───┘             └───┘                                              │
  │  ← 중심 간 거리 = 3W →                                               │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  2) 병행 배선 길이 최소화: 나란히 달리는 구간이 길수록 결합 심해짐.
  3) GND 가드 라인: Aggressor와 Victim 사이에 GND 배선 삽입 → 전계 차폐.
  4) 레이어 교대: 인접 신호층 배선을 수직/수평으로 교차 → 결합 최소.
  5) 차동 신호: 두 선이 반대 신호를 가짐 → 크로스토크 상쇄.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ EMI: 전자기 간섭 — 왜 발생하고 어디서 나오나 ─────────────────────────┐

  EMI = Electromagnetic Interference (전자기 간섭)
  회로가 의도치 않게 전자기파를 방출하거나 외부 전자기파에 의해 오동작.

  방출 EMI(Emission) 발생 원인:
  - 고속 스위칭 신호 (FPGA 클록, PWM, DDR 데이터)의 고조파 성분
  - 전류 루프 (안테나처럼 동작): 루프 면적 × 전류 변화율 ∝ 방사량
  - 전원 노이즈 (리플이 케이블을 타고 나감)

  방사 EMI의 주요 경로:
  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  PCB 클록 라인                                                        │
  │        │  (고속 엣지 → 고조파 풍부)                                  │
  │        ├─── [방사] ──→ 공중파 방출 (RE: Radiated Emission)           │
  │        │                                                              │
  │        └─── [전원] ──→ 전원 케이블 전도 (CE: Conducted Emission)     │
  │                                                                       │
  │  전류 루프 면적과 방사량:                                             │
  │                                                                       │
  │  E ∝ A × I × f²   (A=루프면적, I=전류, f=주파수)                    │
  │                                                                       │
  │  → A를 줄이는 것이 EMI 저감의 핵심                                  │
  │  → 신호 배선 바로 아래에 GND 플레인이 있으면                        │
  │     전류 복귀 경로가 GND 플레인으로 신호선 바로 아래를 타고 옴      │
  │  → 루프 면적 = 신호선과 GND 사이의 얇은 층 = 매우 작음 → EMI 감소  │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  EMC 규격 (방산/군용):
  MIL-STD-461G: 방산 장비의 EMI/EMC 시험 표준
  - CE101/102: 전도 방출 (전원선 및 신호선)
  - RE101/102: 방사 방출 (자계/전계)
  - CS101/114/115/116: 전도 감수성 (외부 EMI에 얼마나 강한가)
  - RS101/103: 방사 감수성

  광운대 방공여단 시스템에서 EMC가 중요한 이유:
  레이더 방사 전자기파가 카메라 전자회로에 간섭 가능.
  반대로 서버/PC에서 나오는 EMI가 레이더 수신에 간섭 가능.
  → 시스템 통합 시 EMC 격리 설계가 시스템 신뢰성의 핵심.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ 페라이트 비드(Ferrite Bead): EMI 필터의 핵심 소자 ─────────────────────┐

  페라이트 비드는 저항처럼 생겼지만 주파수에 따라 임피던스가 달라진다.
  저주파: 인덕터처럼 동작 (신호 통과)
  고주파(수십 MHz 이상): 저항처럼 동작 (에너지를 열로 소모 → 감쇠)

  → 전원 라인에 직렬로 삽입하면 DC/저주파 전력은 통과, 고주파 노이즈는 차단.

  예: 광운대 서버룸 전원 필터
  교류 220V → EMI 필터(페라이트 코어 + 커패시터) → 파워서플라이
  → 그리드 노이즈 차단 + 장비 EMI 역류 차단 (양방향 역할)

  └──────────────────────────────────────────────────────────────────────────┘

  P4.  High-Speed 배선 (DDR / USB3.0 / HDMI)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ DDR4 배선: 가장 어려운 병렬 고속 버스 ─────────────────────────────────┐

  DDR4 = Double Data Rate 4 SDRAM
  클록 상승/하강 엣지 모두에서 데이터 전달 → 3200MHz 클록 = 6400Mbps/핀.
  RK3399에 LPDDR4를 붙일 때 이 규칙을 지켜야 함.

  DDR4 신호 그룹:
  - CK/CK#: 차동 클록 (DRAM의 심장)
  - CA: Command/Address (어떤 주소에 읽기/쓰기 명령)
  - DQ: 데이터 (8개 = 1바이트 레인)
  - DQS/DQS#: 데이터 스트로브 (DQ 샘플링 타이밍 기준)

  Fly-by 토폴로지:
  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  T-분기(나쁜 예, 과거 DDR2):                                          │
  │                                                                       │
  │  컨트롤러 ──────┬───────┬────── 종단                                 │
  │                 │       │                                             │
  │               DRAM0   DRAM1   ← 분기점에서 반사 발생!               │
  │                                                                       │
  │  Fly-by(DDR3/4 표준):                                                │
  │                                                                       │
  │  컨트롤러 ── DRAM0 ── DRAM1 ── DRAM2 ── 종단저항                   │
  │                                                                       │
  │  → 신호가 직렬로 통과, 반사 없음                                     │
  │  → 하지만 각 DRAM에 신호 도달 시간이 다름(비행 시간 차이)           │
  │  → Write Leveling으로 소프트웨어 보정                                │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  등장 매칭 (Length Matching):
  DQ 그룹(8비트) 내에서 각 배선 길이를 ±25mil 이내로 맞춤.
  → 모든 비트가 동시에 DQS에 정렬되어 도착.
  길이 차이 = 전파 지연 차이 = 타이밍 스큐.
  FR4에서 전파 속도 ≈ 167 ps/inch → 25mil 차이 = 4.2ps 스큐.

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ USB3.0 차동쌍 배선 ─────────────────────────────────────────────────────┐

  USB3.0 SuperSpeed: 5Gbps 직렬 데이터, 차동쌍(D+, D-)으로 전송.
  임피던스: 90Ω 차동 (각 선은 45Ω 단일).

  차동 신호의 장점:
  - D+ = 신호, D- = 반전 신호 → 수신기는 D+ - D- 만 사용
  - 외부 노이즈(크로스토크, EMI)는 D+, D-에 같은 방향으로 유도됨
    → 빼면 상쇄! 이것이 CMRR (공통 모드 제거)
  - 따라서 차동 신호는 노이즈에 훨씬 강함.

  USB3.0 배선 규칙:
  - 차동쌍 내 등장 매칭: |L+ - L-| ≤ 5mil
  - 90° 직각 코너 금지 → 45° 또는 아크(Arc) 라우팅
  - 층 변경 시 GND 비아를 신호 비아 양옆에 추가 (리턴 경로 유지)
  - AC 커플링 커패시터 100nF (SS 라인) — 수신단 DC 분리

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  잘못된 배선(직각):   올바른 배선(45°):   더 좋은 배선(아크):        │
  │                                                                       │
  │  ────────┐            ──────╲             ────╮                      │
  │          │                   ╲                 ╰───                  │
  │          └────                ────            (곡선)                 │
  │                                                                       │
  │  직각 코너에서 배선 폭이 넓어지는 효과 → 임피던스 불연속 → 반사     │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ HDMI: 영상 신호 고속 직렬 전송 ────────────────────────────────────────┐

  HDMI 2.0: 4K 60fps 영상 전송. 총 4쌍의 TMDS 차동 채널.
  - 3개 데이터 채널 (TMDS Data 0/1/2): 각 6Gbps
  - 1개 클록 채널 (TMDS Clock)
  - 임피던스: 100Ω 차동

  EO-IR 카메라 출력으로 HDMI 2.0 사용 시:
  FPGA에서 H.265 디코딩 후 HDMI 출력 IP 코어 → TMDS 인코딩 → 모니터.

  배선 규칙:
  - 4쌍(채널) 간 등장 매칭: ±100mil 이내 (클록 기준)
  - 각 채널 내부 P/N 선 등장 매칭: ±5mil
  - 차동쌍 사이 간격: ≥ 3×배선폭 (크로스토크 억제)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ 임피던스 매칭: 왜 50Ω인가 ─────────────────────────────────────────────┐

  RF 시스템의 모든 것이 50Ω으로 표준화되어 있다.
  이유: 최대 전력 전달 = 소스 임피던스와 부하 임피던스가 같을 때.
  ZS = ZL* (켤레 매칭 — 복소수의 경우 허수부 반전)
  순수 저항계에서: ZS = ZL = 50Ω.

  50Ω이 선택된 이유는 전력 전달과 신호 감쇠의 최적 절충점.
  (이론적으로 75Ω이 최소 감쇠, 30Ω이 최대 전력 — 50Ω이 타협점)

  임피던스 불일치 결과:
  반사 손실(Return Loss) = -20 × log|Γ| [dB]
  Γ = 0.1 → |Γ|² = 1% 전력 반사 → Return Loss = 20dB (좋음)
  Γ = 0.5 → 25% 전력 반사 → Return Loss = 6dB (나쁨)

  └──────────────────────────────────────────────────────────────────────────┘

  ┌ Smith Chart: 임피던스를 반사 계수 평면에 그린 것 ──────────────────────┐

  Smith Chart는 복소 반사 계수 Γ 평면을 임피던스 등고선으로 표시한 도구.

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │                    Smith Chart 구조                                   │
  │                                                                       │
  │              jX = +∞ (유도성, 상단)                                  │
  │                    │                                                  │
  │   R=0  ────────────●──────────── R=∞                                 │
  │  (단락)       중심=50Ω           (개방)                               │
  │            R=Z0,X=0              │                                   │
  │                    │                                                  │
  │              jX = -∞ (용량성, 하단)                                  │
  │                                                                       │
  │  등저항 원: 중심이 R축 위에 있는 원들 (R=0, 1, 2, 5, 10, ∞ 등)     │
  │  등리액턴스 원: 차트 위아래로 휘어진 원호들 (X=0.5, 1, 2 등)        │
  │                                                                       │
  │  L 추가 → 시계방향으로 점 이동 (위로)                                │
  │  C 추가 → 반시계방향으로 점 이동 (아래로)                            │
  │  직렬 소자 → 등저항 원을 따라 이동                                   │
  │  병렬 소자 → 어드미턴스 차트에서 등컨덕턴스 원을 따라 이동          │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  드론 레이더 안테나 매칭 예시:
  패치 안테나 측정값: Z = 30 + j20 Ω @ 77GHz
  목표: 50Ω (레이더 RF 프론트엔드)
  → Smith Chart에서 (30+j20)을 찾고 L/C 추가하며 중심으로 이동
  → 설계 결과: 직렬 L 0.3nH + 병렬 C 0.1pF = 50Ω 매칭 달성

  └──────────────────────────────────────────────────────────────────────────┘

  R2.  Phase Noise
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Phase Noise의 물리적 이해:

  이상적인 발진기: v(t) = A × cos(2π × f0 × t)  — 완벽한 정현파.
  실제 발진기:     v(t) = A(t) × cos(2π × f0 × t + φ(t))
  → A(t): 진폭 잡음 (AM 노이즈) — 보통 작고 리미터로 억제 가능
  → φ(t): 위상 잡음 (PM 노이즈) — 억제 어려움, 스펙트럼 확산 원인

  위상이 흔들리면 스펙트럼에서 반송파 주위에 "치마(Skirt)"처럼 퍼짐.
  이것이 Phase Noise 스펙트럼 — 단위 dBc/Hz.

  레이더에서 Phase Noise가 중요한 이유:
  도플러 레이더는 표적의 미세한 주파수 편이(도플러 주파수)를 탐지.
  LO(Local Oscillator)의 위상 잡음이 이 도플러 신호를 가리면 → 탐지 불가.

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  Phase Noise가 나쁜 경우:                                             │
  │                                                                       │
  │  dBc/Hz                                                               │
  │     0  │                                                              │
  │   -40  │   ╲                                                          │
  │   -60  │    ╲──────────────  ← Phase Noise floor 높음               │
  │   -80  │                  ↑  도플러 신호가 이 아래에 있으면 못 봄    │
  │  -100  │                                                              │
  │         └──────────────────────────────── offset freq (Hz)            │
  │                                                                       │
  │  Phase Noise가 좋은 경우:                                             │
  │  dBc/Hz                                                               │
  │     0  │                                                              │
  │   -80  │   ╲                                                          │
  │  -100  │    ╲────────────── ← Phase Noise floor 낮음                │
  │  -120  │                  ↑  도플러 신호 탐지 가능!                  │
  │         └──────────────────────────────── offset freq (Hz)            │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  Leeson 모델 (VCO 위상 잡음 이론값):
  L(fm) = 10×log{(2FkT/P0) × [1 + (f0/(2×QL×fm))²] × (1 + fc/fm)}
  fm: 오프셋 주파수, F: 잡음 지수, QL: 부하 Q, fc: 플리커 코너 주파수
  → QL이 높을수록 (공진기 품질이 좋을수록) 위상 잡음 낮아짐.

  R3.  LNA / Mixer / VCO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ 레이더 수신기 신호 흐름 전체 ──────────────────────────────────────────┐

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │  안테나 (77GHz, -80dBm 신호 수신)                                      │
  │       │                                                                 │
  │       ▼                                                                 │
  │  [BPF: 대역통과 필터]  ← 원하는 주파수 대역만 통과, 나머지 차단       │
  │       │                                                                 │
  │       ▼                                                                 │
  │  [LNA: 저잡음 증폭기]  ← 신호를 20~25dB 증폭, 잡음 최소로 추가      │
  │       │                    → 여기서 NF가 시스템 NF 대부분 결정         │
  │       ▼                                                                 │
  │  [Mixer]  ←── [VCO/PLL: 로컬 오실레이터 77GHz]                        │
  │       │                                                                 │
  │       │ 주파수 변환: fIF = fRF - fLO                                   │
  │       │ (77.1GHz 수신 - 77.0GHz LO = 100MHz IF)                       │
  │       ▼                                                                 │
  │  [IF 필터 + 증폭기]  ← 중간주파수(IF) 신호 처리                       │
  │       │                                                                 │
  │       ▼                                                                 │
  │  [ADC]  ← IF 신호를 디지털화 (고속 Flash 또는 Pipeline ADC)            │
  │       │                                                                 │
  │       ▼                                                                 │
  │  [FPGA/DSP: FFT + CFAR + 표적 추적]                                    │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  LNA (Low Noise Amplifier):
  안테나에서 오는 신호는 수신 거리가 멀수록 매우 약함 (수신 전력 -80~-100dBm).
  이걸 증폭하는 첫 번째 소자 = LNA.
  "저잡음"이 핵심: LNA 자체가 노이즈를 최소한으로 추가해야 함.

  Friis 공식: 시스템 전체 잡음 지수
  F_total = F1 + (F2-1)/G1 + (F3-1)/(G1×G2) + ...
  F1=LNA 잡음지수, G1=LNA 이득, F2=Mixer 잡음지수...
  → G1이 크면 F2/(G1)은 작아짐 → LNA 이득이 클수록 뒤 단 노이즈 희석!
  → LNA의 낮은 NF + 높은 이득이 시스템 성능 결정.

  Mixer:
  두 주파수의 신호를 곱하면 합/차 주파수 성분 생성.
  cos(ω_RF × t) × cos(ω_LO × t) = 0.5×[cos((ω_RF-ω_LO)t) + cos((ω_RF+ω_LO)t)]
  → (ω_RF - ω_LO)가 IF (원하는 것), (ω_RF + ω_LO)는 필터로 제거.
  길버트 셀(Gilbert Cell): 트랜지스터 쿼드로 구성한 이중 평형 믹서.
  높은 LO/RF 격리도, 짝수 고조파 억제.

  └──────────────────────────────────────────────────────────────────────────┘

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌ FMCW 레이더 완전 해설 — 드론 탐지 시스템 ─────────────────────────────┐

  FMCW = Frequency Modulated Continuous Wave (주파수 변조 연속파)
  연속적으로 전파를 쏘되 주파수를 시간에 따라 선형으로 변화시키는 레이더.

  FMCW 원리:
  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  송신 신호 (Chirp):                                                   │
  │  f↑                                                                  │
  │   │  /  /  /  /  /    ← 주기 T마다 B Hz (대역폭) 스윕               │
  │   │ /  /  /  /  /                                                     │
  │   │/  /  /  /  /                                                      │
  │   └──────────────── t                                                 │
  │   f0         f0+B                                                     │
  │                                                                       │
  │  거리 R의 표적에서 반사된 수신 신호:                                  │
  │  f↑                                                                  │
  │   │    /  /  /  /    ← τ = 2R/c 만큼 지연                           │
  │   │ __/  /  /  /                                                      │
  │   └──────────────── t                                                 │
  │        ←τ→                                                            │
  │                                                                       │
  │  비트 주파수 (거리 정보):                                             │
  │  fb = (B/T) × τ = (B/T) × (2R/c) = 2BR / (cT)                      │
  │  → R = fb × c × T / (2B)                                             │
  │                                                                       │
  │  거리 분해능:  ΔR = c / (2B)                                          │
  │  예: B=4GHz → ΔR = 3×10⁸ / (2×4×10⁹) = 0.0375m = 3.75cm           │
  │                                                                       │
  │  속도 측정 (도플러):                                                  │
  │  여러 처프를 연속 전송 → 같은 거리 셀에서 처프 간 위상 변화 관찰    │
  │  fd = 2v × f0 / c  → v = fd × c / (2 × f0)                          │
  │  예: f0=77GHz, fd=1kHz → v = 1000×3×10⁸/(2×77×10⁹) = 1.95 m/s    │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  CFAR (Constant False Alarm Rate) 처리:
  FFT로 거리-속도 맵을 얻은 후 표적을 탐지할 때
  고정 임계값을 쓰면 → 노이즈 레벨이 달라질 때 오탐/미탐 발생.
  CFAR: 각 셀 주변의 평균 노이즈 레벨을 동적으로 추정해서 임계값 결정.
  → 노이즈 환경이 바뀌어도 오경보율을 일정하게 유지.

  광운대 방공여단 레이더-카메라 연동:
  레이더가 방위각/고각/거리 큐(Cue) 제공 → Pan-Tilt 명령
  → EO-IR 카메라가 해당 방향으로 자동 조준 → 광학 확인.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  JTAG (IEEE 1149.1): PCB 레벨 테스트 표준

  BGA 패키지 칩(공 모양 솔더 패드)이 PCB에 납땜되면
  X-ray 없이는 솔더 불량을 확인할 방법이 없다.
  Boundary Scan은 각 IC의 모든 I/O 핀에 테스트 셀을 붙여서
  소프트웨어로 핀 상태를 강제 설정/읽기 가능하게 한다.

  ┌───────────────────────────────────────────────────────────────────────┐

  │  PCB 상의 JTAG 체인:                                                  │
  │                                                                       │
  │  JTAG 헤더                                                            │
  │  (TDI,TDO,TCK,TMS,nTRST)                                             │
  │       │                                                               │
  │  TDI ─→ [FPGA BSR] ─→ [MCU BSR] ─→ [DDR BSR] ─→ TDO               │
  │                                                                       │
  │  BSR = Boundary Scan Register (각 IC의 테스트 레지스터)              │
  │                                                                       │
  │  테스트 예시 — 솔더 연결 확인:                                       │
  │  1) FPGA의 GPIO 핀에 1 출력 → MCU의 GPIO 핀에서 1 읽히는지 확인     │
  │  2) 0으로 바꾸어 다시 확인                                           │
  │  → 오픈(단선)이면 상태 변화 없음, 쇼트(단락)이면 의도치 않은 변화   │

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  BIST (Built-In Self-Test): 칩이 스스로 자신을 테스트
  LFSR (Linear Feedback Shift Register): 의사 난수 패턴 생성기

  ┌───────────────────────────────────────────────────────────────────────┐
  │                                                                       │
  │  4비트 LFSR (탭: X^4+X^3+1):                                         │
  │                                                                       │
  │  ┌──┐   ┌──┐   ┌──┐   ┌──┐                                           │
  │  │D3│ → │D2│ → │D1│ → │D0│ → 출력 시퀀스                           │
  │  └──┘   └──┘   └──┘   └──┘                                           │
  │    ↑                    │                                             │
  │    └──── XOR ───────────┘  피드백 탭                                 │
  │                                                                       │
  │  초기값(Seed): 0001                                                   │
  │  순서: 0001→0011→0111→1110→1101→1011→0110→1100→1001→0010→            │
  │        0100→1000→0001 (주기: 2^4-1=15)                               │
  │  → 완전히 예측 가능하지만 "랜덤처럼 보이는" 패턴                    │
  │  → 이 패턴으로 회로를 자극 → MISR로 응답 압축 → PASS/FAIL 판정     │
  │                                                                       │
  └───────────────────────────────────────────────────────────────────────┘

  ATPG (Automatic Test Pattern Generation):
  Stuck-at 고장 모델: 배선이 항상 0 또는 1에 고착된 결함.
  ATPG는 각 결함을 탐지하기 위한 최소 패턴 세트를 자동으로 계산.

  탐지 과정:
  1) 결함 활성화: 결함 노드를 반대 값으로 만드는 입력 적용
     (SA0 결함 → 그 노드를 1로 만드는 입력)
  2) 결함 전파: 결함 효과를 출력 핀까지 전달하는 경로 설정
  3) 출력 비교: 정상 회로 출력 vs 결함 회로 출력이 다르면 탐지 성공.

  ECG 신호: 심장 전기 활동 → 피부 표면 전위차 측정.
  신호 크기: 0.1~5mV (매우 작음!)

  - 몸 움직임에 의한 모션 아티팩트

  Flash 프로그래밍 순서:
  1) SYSRESETREQ로 타겟 리셋 → Debug 모드로 정지
  2) Flash Unlock: FLASH->KEYR에 키값 두 번 쓰기 (0x45670123, 0xCDEF89AB)
  3) Flash Erase: 섹터 지우기 (최소 단위 128Byte~128KB, MCU마다 다름)
  4) Flash Write: 16비트 반단어(Half-Word) 단위로 쓰기
  5) Flash Lock: 재잠금 (의도치 않은 쓰기 방지)
  6) 리셋 후 정상 실행

  OpenOCD + GDB 디버그 명령 예시:
  target remote localhost:3333   → OpenOCD에 GDB 연결

  ┌ Pan-Tilt PID 제어 상세 ─────────────────────────────────────────────────┐

  PID (Proportional-Integral-Derivative) 제어:
  목표 위치와 현재 위치의 오차(Error)를 이용해서 모터 출력을 계산.

  e(t) = θ_target - θ_current  (위치 오차)

  PID 출력:
  u(t) = Kp×e(t) + Ki×∫e(t)dt + Kd×de(t)/dt

  Kp (비례): 오차에 비례한 출력. 클수록 빠른 응답, 너무 크면 발진.
  Ki (적분): 잔류 오차 누적 → 정상 상태 오차 제거. 너무 크면 오버슈트.
  Kd (미분): 오차 변화율에 반응 → 진동 댐핑. 노이즈에 민감.

  ─────────────────────────────────────────────────────────────────────────
  ① Razavi — "Design of Analog CMOS Integrated Circuits" 2nd Ed.
     : MOSFET 소신호 모델, 차동쌍, OPAMP 설계의 완전 이론.
       Chapter 7 (Noise), Chapter 9 (Cascode) 집중 공부.

  ② Willy Sansen — "Analog Design Essentials"
     : 노이즈 버짓, GBW-Phase Margin 트레이드오프 실무 중심.

  ③ Kester — "The Data Conversion Handbook" (Analog Devices, 무료 PDF)
     : ADC/DAC 설계의 완전 레퍼런스. ENOB, 샘플링 이론까지.
     URL: analog.com → resources → technical-books

  PCB / SI / PI
  ─────────────────────────────────────────────────────────────────────────
  ④ Eric Bogatin — "Signal and Power Integrity Simplified" 3rd Ed.
     : 전송선로, 반사, PDN 임피던스를 가장 쉽게 설명한 책.

  ⑤ Mark Montrose — "Printed Circuit Board Design Techniques for EMC"
     : EMC 설계 실무. 그라운드 플레인, 크로스토크, 필터 설계.

  RF
  ─────────────────────────────────────────────────────────────────────────
  ⑥ Pozar — "Microwave Engineering" 4th Ed.
     : 전송선로, S-파라미터, Smith Chart 이론. Chapter 2, 4 핵심.

  ⑦ Razavi — "RF Microelectronics" 2nd Ed.
     : LNA, Mixer, PLL, VCO 회로 설계.

  디지털 / FPGA / 검증
  ─────────────────────────────────────────────────────────────────────────
  ⑧ Weste & Harris — "CMOS VLSI Design" 4th Ed.
     : 합성, P&R, DFT, BIST 완전 커버. ASIC 설계 교과서.

  ⑨ Spear — "SystemVerilog for Verification" 3rd Ed.
     : UVM, 커버리지, 제약 기반 랜덤 검증.

  아날로그
  TIA 출력: Vout = -Iph × Rf
  MOSFET Id: Id = (1/2)×μCox×(W/L)×(Vgs-Vth)²
  gm:        gm = √(2×μCox×(W/L)×Id)
  LDO 출력: Vout = Vref × (1 + R1/R2)
  Thermal N: Vn = √(4kTRB)
  ADC SNR:   SNR_dB = 6.02×N + 1.76
  ENOB:      ENOB = (SINAD - 1.76) / 6.02

  PLL / Jitter / RF
  PLL 출력:  fout = N × fref
  Jitter SNR: SNR = -20×log₁₀(2π×f×tj_rms)
  반사 계수: Γ = (ZL - Z0) / (ZL + Z0)
  Friis NF:  F = F1 + (F2-1)/G1 + (F3-1)/(G1×G2)

  FMCW 레이더
  비트 주파수: fb = 2BR / (cT)
  거리:        R = fb×c×T / (2B)
  거리분해능: ΔR = c / (2B)
  도플러:     fd = 2v×f0 / c
  속도:       v = fd×c / (2×f0)

  PCB 임피던스
  마이크로스트립 Z0 ≈ (87/√(Er+1.41)) × ln(5.98H/(0.8W+T))
  PDN 목표:   Ztarget = ΔV_허용 / ΔI_최대

  PID 제어
  u(t) = Kp×e(t) + Ki×∫e(t)dt + Kd×de(t)/dt
